# SP1b-4f — The PMP enforced, user mode, the arch-test group `pmp32` — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the ESP32-C3's PMP enforced as its TRM describes it (no static priority), the user mode the chip has, and the arch-test group `pmp32` re-enabled in the CI against Sail, the reference firmwares unchanged.

**Architecture:**

| Where | Owns | Why |
|---|---|---|
| `crates/cpu-rv32/src/pmp.rs` (new) | the 16 entries, their WARL writes and locks, the decoding of OFF/TOR/NA4/NAPOT, the two sets of rules (`PmpRules::Specification`, `PmpRules::Esp32C3`), the check of an access, the page verdicts | one PMP for the bench and the chip; only the combination and the WARL details differ |
| `crates/cpu-rv32/src/csr.rs` | `Core` (replaces `VendorCsrs`), `Privilege`, `mstatus` per core, `misa`, `mcounteren` (bench), `MPP` on traps and `mret`, `MPRV`, CSR access by mode | the privileged architecture of each core |
| `crates/cpu-rv32/src/hart.rs`, `exec.rs`, `trap.rs` | the mode of the hart; PMP checks at fetch (per parcel, before the decode cache), load and store; `ecall` from U, `mret` and `wfi` in U, interrupts in U | where the checks happen |
| `crates/cpu-rv32/src/csr_esp32c3.rs` | the ESP32-C3's own CSRs, without the PMP | the PMP moved |
| `crates/emu-cli` (`rvtest.rs`, `main.rs`, tests) | `bench_hart`, the hart `rvtest` and riscv-tests run on; a synthetic failing ELF | conformance bench |
| `tools/conformance/` | ISA (U), Sail override (U, `PMP_Ignore`, `wfi` in U), the patch of the arch-test environment, `pmp32` = 41, `ARCH_TEST_ONLY`, skip list | `pmp32` against Sail |
| `tools/docker/riscof/Dockerfile` | `patch` | applying the patch |

The machine (`soc-esp32c3`) only selects `Core::Esp32C3` and keeps both `ecall`s out of its exception diagnostics. For a GUI (SP2): `Hart::privilege()` says the mode, and a PMP fault shows as the access fault the firmware takes (its diagnostic line is unchanged).

**Tech Stack:** Rust 1.99.0 (edition 2024). No new package. Sail 0.15, riscv-arch-test 3.10.0, RISCOF 1.25.3 in `inkemu/riscof`; QEMU `esp_develop_9.2.2_20250817` in `espressif/idf:v5.5.2`.

**Spec:** `docs/superpowers/specs/2026-10-15-sp1b-4f-design.md` (decisions L1–L12, binding). Research: `docs/research/esp32c3-pmp-and-user-mode.md`. ADR 0010.

**What was verified, and where.** On the development host (load average 10 to 37 on 16 cores, shared with other work): `cargo fmt --all --check`; `tools/ci/clippy.sh` (`-D warnings`) on `cpu-rv32`, `soc-esp32c3`, `emu-cli`, `lockstep` (all targets, all features); rustdoc (`-D warnings`, private items) on the same four; `cargo check --target wasm32-unknown-unknown` on `cpu-rv32`, `soc-esp32c3`, `lockstep`; the non-ignored tests of `cpu-rv32`, `soc-esp32c3`, `emu-cli`, `lockstep`; the pinned trace hashes of `flash_hello.bin` (12 s `a0d221296337b295`; 40 000 001 cycles `fb9ea628bc25b355`), `adc_wait_panic` and `deep_sleep_timer`; CoreMark at `--max-time 6` (`b9d7c2623875226c`, as before the change) and `--max-time 2`; the arch-test group `pmp32` alone (`ARCH_TEST_ONLY=pmp32`, 41 of 41) and its mutation (38 of 41 fail); the lockstep window `hello` against QEMU. **Not run on that host**, left to the CI: `cargo test --workspace`, the other `#[ignore]` suites (the CoreMark test at 20 s among them), coverage, the whole arch-test (the 92 tests of the other groups on the new ISA), the windows `nvs` and `nvs-ota`.

## Global Constraints

- The default machine does not change for the reference firmwares: the pinned trace hashes stay, the windows of the lockstep, their counts and usages stay.
- No supervisor mode: the chip has none.
- The tests of riscv-arch-test are not modified; the environment's patch is versioned, checked against the original's hash, and applied the same to both models.
- QEMU, Sail and ESP-IDF run only in their pinned images, one container at a time.
- Commits: `type(scope): description`, no trailer.

## Rulings taken while doing it

| # | Ruling | Why |
|---|---|---|
| R79 | **The ESP32-C3 core gets its user mode** (L1): `misa` `0x40101104` (TRM register 1.6; it read `0x40001104`); `mret` with `MPP` = 0 enters it; in it a CSR above the mode, `mret`, and `wfi` under `TW` are illegal instructions, `ecall` has cause 8, an interrupt is taken whatever `MIE`. No `MPRV`, no `mcounteren`: the TRM's CSR list and `mstatus` register name neither. | The TRM; the limit "SP1b-4f" written on `CsrFile::return_privilege` in SP1b-4c is lifted. |
| R80 | **The chip's PMP has no static priority** (L2), with the readings of PM §2 (a partial overlap grants nothing; NAPOT above 1 GB decoded as the specification does, an ASSUMPTION a chip settles). | TRM §1.8.2; equal to QEMU's static priority on ESP-IDF's 16 contiguous TOR entries. |
| R81 | **WARL: the chip as QEMU, the bench as Sail** (L3, L6). Both ignore a write of R = 0 with W = 1 (QEMU's `pmp_write_cfg`; Sail configured `PMP_Ignore`); the chip keeps bits 5–6 and 32 address bits, the bench reads bits 5–6 as 0 and keeps 30 address bits (Sail's `physaddr_bits` 32). The SP1b-2 test that pinned "stored verbatim, reserved bits included" (`0x62`, R = 0 with W = 1) is replaced by one test per rule. | The lockstep's oracle for the chip; the conformance reference for the bench. |
| R82 | **Checked per parcel, before the decode cache** (L4). The decode cache holds decodings only: a PMP write takes effect at the next fetch with nothing to invalidate. Verified by mutation: without the check on a cache hit, `a_cached_decoding_does_not_bypass_a_pmp_written_after_it` fails; undone. | Task: the decode cache must be invalidated or checked when the PMP changes. |
| R83 | **Page verdicts and per-mode masks** (L5). The random test `page_verdicts_agree_with_the_rules_on_random_configurations` (400 configurations, 200 accesses each, both rules) found an inverted argument of `overlap` in the first version (the page inside the entry, not the entry inside the page); fixed before any commit. | ESP-IDF locks all 16 entries: every access of machine mode is checked. |
| R84 | **The conformance bench is `Core::MachineUser`** (L6), for `rvtest`, riscv-tests and riscv-arch-test. The `rv32ui` tests now run in user mode (the `p` environment enters it when the hart has it), `rv32mi-p-csr` uses `mcounteren`, `rv32mi-p-pmpaddr` passes and leaves the skip list: 65 run, 2 skipped (64 and 3 before). | Sail cannot model the chip's rule; the shared code is checked on the bench, the chip's rule by unit tests. |
| R85 | **`Core` replaces `VendorCsrs`** (L7): `MachineOnly` (default), `MachineUser`, `Esp32C3`; `Privilege`, `Hart::privilege()`; the PMP in `cpu_rv32::pmp` (its constants `PMPCFG0`, `PMPADDR0`, `PMP_ENTRIES` public there). | The core is more than a vendor's CSRs. |
| R86 | **`pmp32` with the environment patched** (L8). A boot hook (`RVMODEL_BOOT` stepping over the first traps) was tried first on Sail: it passes `medeleg`, but the S prolog then traps outside the code segment and the environment loops (trace of `PMP-CFG-reg`, 300 000 instructions); kept out. With the patch, the 41 tests end on Sail M+U, then pass on inkemu: 41 of 41 (`ARCH_TEST_ONLY=pmp32`, 2026-10-15). Mutation: the bench given the chip's rules (no priority, its WARL) fails 38 of 41; undone. | Measured, PM §5. |
| R87 | **`ARCH_TEST_ONLY`** limits `run-arch-test.sh` to the named groups, each with its pinned count, the total recomputed; an unknown group exits 2. The CI does not set it. | A local check of one group without changing the pins. |
| R88 | **A synthetic failing ELF** for `rvtest_cli::failing_test_exits_one_and_names_the_sub_test` (L9), built by the test (ELF32 header, one `PT_LOAD`, a symbol table with `tohost`): it writes `(1 << 1) | 1` to `tohost`. | SP1a's hand-over: the test relied on `pmpaddr` failing. |
| R89 | **No lockstep row** (L10): row 26 stays true (QEMU's kept R, W, X bits are in entries that are off), its sentence on the PMP not being enforced is revised by a dated note, and so is row 1's on user mode. The synthetic test `a_csrrsi_writes_only_its_immediate` sets R and W with the immediate 3 (and `gp` all ones for the register reading) instead of W alone, the reserved combination both models now ignore; it still fails if the tool reads the immediate as a register. | A row belongs to a window that uses it (R35). |
| R90 | **The cost is not measurable on the development host.** CoreMark at `--max-time 2`, four interleaved pairs, user CPU time: before 22.8, 16.2, 32.3, 31.1 s; after 27.8, 27.2, 49.5, 28.6 s (medians 27.0 and 28.2 s); at `--max-time 6`, one run each: 88.1 s before, 68.7 s after. The load moved between 10 and 37 during the runs, more than the change: the CI's duration of the CoreMark test (68 s in SP1b-4e) is the reference to watch. | No hardware counters (`perf_event_paranoid` 4); numbers say where they come from (R72, R78). |
| R91 | **The pinned hashes are unchanged** (L11), checked locally: 12 s `a0d221296337b295`, `fb9ea628bc25b355`, `b217bc3b287080ae`, `80bd1c43d55b5467`; CoreMark's `trace-hash` at 2 s and 6 s equal before and after. The CoreMark test itself (20 s, `bfb20978732b673f`) is left to the CI. | No PMP fault in these runs. |
