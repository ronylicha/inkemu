# SP2e — The SD card of the X4 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** an SD card in SPI mode that CrossPoint 1.6.5's driver (SdFat 2.3.1) initializes, reads and writes; the host's image file it is backed by; a blank FAT32 image made by our code. With SP2d's wiring (§9 of the spec), CrossPoint reaches its home screen.

**Tech Stack:** Rust 1.99.0 (edition 2024). No new dependency of `chips`. `fatfs` 0.3.6 (MIT, `default-features = false`, features `std`, `alloc`) as a **dev-dependency** of `host` only, to read back the images we format.

**Spec:** `docs/superpowers/specs/2026-10-15-sp2e-sd-card-design.md` (decisions 2e-D1 to 2e-D17, binding). Research: `docs/research/sp2e-sd-card.md`. ADR 0014.

## Global Constraints

- `chips` depends on `emu-core` and `thiserror` only, knows no SoC, does no host I/O, builds for `wasm32-unknown-unknown`; its `clippy.toml` and `crates/boards/tests/host_io_ban.rs` are unchanged.
- Time is device time: `Cycles` of the time base the card is built with; durations in nanoseconds converted by `Frequency::nanos_to_cycles`. No host clock.
- `soc-esp32c3`, `boards` and `session` are not touched (SP2b and SP2d work there).
- Commits `type(scope): description`, no trailer, paths given to `git commit -- <paths>`; nothing pushed.
- Local checks (`CARGO_BUILD_JOBS=3`): `cargo fmt --all --check`, `tools/ci/clippy.sh` (or `cargo clippy --all-targets`) on `chips`, `host`, `emu-cli`, their unit tests, `cargo check --target wasm32-unknown-unknown -p chips`, `cargo doc --no-deps` on the three crates without warning. Left to the CI: `cargo test --workspace`, coverage, `cargo deny`.

## Rulings

| # | Ruling | Why |
|---|---|---|
| 2e-R1 | **Test first, every task**: the failing test is committed with the change that makes it pass, in the same commit; a test names the behaviour, not the function. | Repository rule. |
| 2e-R2 | **One test per command and per state** of spec §6 point 1; a test sends the bytes a host sends (command, CRC, fill bytes) through `exchange`/`transfer`, never a private method. | The interface is the bytes. |
| 2e-R3 | **No panic from the bus.** No `[]` indexing on data the firmware controls, no unchecked arithmetic on an address or a length; a test drives a deterministic pseudo-random stream of bytes, selections and instants through the card and through an empty slot. | 2e-D10. |
| 2e-R4 | **The answer timing is fixed**: the response of a command is on the second byte after its last; a data token comes after the read access time; busy is `00h`; idle while selected is `FFh`. Tests assert byte positions. | 2e-D4, 2e-D7; SdFat discards the first byte (RS §2 point 5). |
| 2e-R5 | **Every value no source gives** is a field of `SdTiming`, `Cid` or `SdCardConfig`, or an `ASSUMPTION:` in the code, and is listed in RS §5. | The repository's rule on hypotheses. |
| 2e-R6 | **Storage errors are the card's errors**, never a panic and never silent: a read error gives the data error token `01h`, a write error the data response `xxx01101b`, both set the R2 "error" bit and leave a `StorageFailed` diagnostic. | 2e-D10. |
| 2e-R7 | **The image file is written in place only through a journal** that was flushed and renamed first; nothing else writes the image. A test interrupts the save between each step (journal temporary written, renamed, half applied) and reopens. | 2e-D13. |
| 2e-R8 | **A blank image is deterministic**: two creations of one size and label give the same bytes; no clock, no random serial. | 2e-D15; reproducible tests and sessions. |
| 2e-R9 | **The X4's wiring, the session format and the interface are SP2d's**: SP2e writes no `SpiTarget` impl (SP2b's trait is not on `main`), no profile key, no session field, no UI code; spec §9 lists them with their SP2d task. | Spec §1, §9. |

### Task 2: Block storage (TDD, `chips::sdcard::storage`)

- [ ] Tests: `MemoryStorage::new` reads zeros and keeps a written block; `from_bytes` refuses a length that is not whole blocks; a block past the end is `StorageError::OutOfRange`; `Overlay` reads the base until a block is written, then the written block; an erased range reads zeros, a block written inside it afterwards reads what was written; `changes()` lists erased ranges merged and sorted, then written blocks in order, and a block written then erased is not listed; erasing 2³² blocks of a 2³²-block base keeps one range; `SparseBlocks` reads zeros where nothing was inserted and refuses a block past its end.
- [ ] Implement; `cargo test -p chips`; wasm check; commit.

### Task 3: CRCs and registers (TDD, `chips::sdcard::{crc, registers}`)

- [ ] Tests: CRC7 of `40 00 00 00 00` is `4Ah` (`95h` with its end bit) and of `48 00 00 01 AA` is `43h` (`87h`); CRC16 of 512 bytes of `FFh` is `7FA1h`; `Capacity::new` gives SDSC with the C_SIZE, C_SIZE_MULT and READ_BL_LEN that code it back (64 MiB, 1 GiB, 1.5 GiB, 2 GiB), SDHC above 2 GiB, refuses 0, a non-whole number of blocks, a SDSC size no field codes, an SDHC size not of 512 KiB, a size beyond `3FFEFFh`; the CSD of each kind decodes back to its capacity by the PLS formula and carries a valid CRC7, `TMP_WRITE_PROTECT` when asked; the CID carries its fields and a valid CRC7; the SCR and the OCR as RS §5 says.
- [ ] Implement; commit.

### Task 4: The card in SD mode, CMD0, the idle state, initialization (TDD, `chips::sdcard`)

- [ ] Tests: before CMD0 the card drives nothing and ignores other commands and a CMD0 with a bad CRC, each with its diagnostic; CMD0 with CS low answers `01h` on the second byte; CMD8 echoes, refuses a bad CRC with `09h`, answers VCA 0 for another voltage; ACMD41 keeps `01h` until 50 ms after the first, then `00h`; an SDHC without CMD8 or with HCS 0 stays idle with its diagnostic; CMD58 before and after; commands other than the idle ones answer `05h`; CMD55 then an undefined ACMD runs the regular command; CMD59 turns checking on and a command with a bad CRC then answers its R1 with bit 3.
- [ ] Implement the byte machine (phases, output queue, command parser); commit.

### Task 5: Reads (TDD)

- [ ] Tests: CMD17 on SDHC gives `FFh` until the access time, `FEh`, the block, its CRC16; on SDSC a partial block after CMD16, an address across a block boundary `20h`, a block length over 512 `40h`; an address past the card `40h`; CMD18 streams blocks each after the access time until CMD12, whose R1 comes on the second byte after it; a block past the end gives the error token `08h`; CMD9 and CMD10 give their registers as data blocks; a storage failure gives `01h` and the R2 error bit.
- [ ] Implement; commit.

### Task 6: Writes, erase, status (TDD)

- [ ] Tests: CMD24 + `FEh` + block + CRC gives `E5h`, then `00h` for 1 ms, then `FFh`, and the block is in the storage; CRC on and a bad CRC16 gives `EBh` and nothing written; CMD25 with `FCh` blocks and `FDh`; a write-protected card answers `EDh` and CMD13 shows `00h 20h` once; ACMD22 counts the well written blocks of the last multiple write; CMD32/33/38 erase the range (zeros), `10h` for CMD38 without the sequence, `WP erase skip` on a protected card; CMD13 clears what it reports; commands while busy are ignored; reselecting during programming reads `00h`.
- [ ] Implement; commit.

### Task 7: CMD6, ACMD13, ACMD51, ACMD23, ACMD42, unsupported and unknown commands, deselection, robustness (TDD)

- [ ] Tests: CMD6 mode 0 and 1, a switch to function 1 answers `Fh`; ACMD13 R2 and 64 bytes; ACMD51 the SCR; ACMD23 and ACMD42 `00h`; CMD42 and the others of 2e-D5 `UnsupportedCommand`; an index no table lists `UnknownCommand`; deselection in each phase (2e-D8); stray bytes; the diagnostics bound; every diagnostic text distinct; the pseudo-random stream (2e-R3) through a card and through `SdSlot::empty()`, which answers `None` always.
