# SP2d — The wiring of the X4 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** in the desktop application, the X4 turns on with its power key, shows what its firmware draws on the SSD1677, answers its seven keys, sleeps and wakes as the device does, and a session recorded with key presses replays identically. CrossPoint 1.6.5 reaches its first screen ("SD card error"); its home screen needs the SD card of SP2e.

**Architecture:**

| Where | Owns | Why |
|---|---|---|
| `crates/emu-core/src/signals.rs` | `BoardInput`, `BoardInputs`, `Supply` (+ `Rc<RefCell<T>>` impls) | contracts neither the SoC nor a board owns (2d-D8, 2d-D13) |
| `crates/chips/src/ssd1677/lines.rs` | `Ssd1677Lines` (`SpiTarget`, `Clocked`), its line roles (RST, BUSY, SCLK, MOSI, D/C, CS) | the chip side of its pins (2d-D2 to 2d-D5) |

| `crates/soc-esp32c3/src/periph/rtc_cntl/sleep.rs`, `periph/io/` | GPIO deep-sleep wake, pad hold | 2d-D11, 2d-D12 |

**Tech Stack:** Rust 1.99.0 (edition 2024), no new crate; ESP-IDF v5.5.2 in `espressif/idf:v5.5.2` for the firmware; the app's stack of SP2c, unchanged.

**Spec:** `docs/superpowers/specs/2026-10-15-sp2d-x4-wiring-design.md` (decisions 2d-D1 to 2d-D23, binding). Research: `docs/research/sp2d-x4-wiring.md` (FreeInk `111fdcc7`, CrossPoint `1.6.5` at `93e98bb7`). ADR 0013 (task 18).

**Precondition.** SP2b (PR #18) is merged into `main` and this branch is rebased on it before task 1. Spec §9 lists what this plan assumes of SP2b's final traits; task 0 checks each point and amends the spec before any code.

## Global Constraints

- `chips` depends on `emu-core` and `thiserror` only, knows no SoC, does no host I/O, builds for `wasm32-unknown-unknown`; so do `emu-core`, `session`, `boards` (no new I/O there).
- Time is device time: `Nanos` on the signals, `Cycles` of the 160 MHz base in the machine and the journal; the wired SSD1677 counts in cycles of 1 GHz, equal to nanoseconds (2d-D2). No host clock anywhere in the model.
- Every value no source gives is a profile value or an `ASSUMPTION:` in the code, listed in RW §4.
- No third-party code or data copied: FreeInk and CrossPoint are cited by file and line; the reference firmware is written from the SSD1677 datasheet and ESP-IDF's documentation.
- Commits `type(scope): description`, no trailer, paths given explicitly to `git commit -- <paths>`; nothing pushed.
- Local checks (`CARGO_BUILD_JOBS=3`): `cargo fmt --all --check`, `tools/ci/clippy.sh` on the crates touched, their unit tests, `cargo check --target wasm32-unknown-unknown` on `emu-core`, `chips`, `session`, the app's checks, the ignored suites that need the reference build one container at a time. Left to the CI: `cargo test --workspace`, coverage, CoreMark, the WebAssembly step as a whole.

## Rulings

| # | Ruling | Why |
|---|---|---|
| 2d-R1 | **Test first, every task**: the failing test is committed with the change that makes it pass, in the same commit, and the test names the behaviour, not the function. | Repository rule; the plan's steps say which test comes first. |
| 2d-R2 | **One path for an input.** A board input reaches a chip only through `Esp32C3::send_board_input` and its application by the machine at its date; no front end, test or replay calls `BoardInputs::apply` itself. A test that needs a key pressed sends a board input. | 2d-D8: the live run and the replay must be the same run. |
| 2d-R3 | **The chip never sees the SoC, the SoC never sees a button.** `chips` implements the traits; `soc-esp32c3` knows `BoardInput` as a target and a value; `boards` alone maps a target to a chip and a pin to a role. `host_io_ban.rs` and the crates' `clippy.toml` are unchanged. | Spec §3.2; 2d-D1. |
| 2d-R4 | **A bare machine stays bare.** `DeviceProfile::instantiate*` attaches nothing and presses nothing; the lockstep windows, `reference_signals` and the SoC's own tests keep it. Only `boards::Wired::power_on` wires and hands the power-on gesture. | 2d-D23. |
| 2d-R5 | **A pinned hash changes only with a reason in the commit message.** Running every reference firmware through the wired machine (`inkemu run`) is expected to keep its trace hash, since none reads the X4's pins; a firmware whose hash moves is investigated before it is re-pinned. | Spec §6 point 8. |
| 2d-R6 | **Released lines** (`driven(None)`): RST reads high, CS deselects, SCLK, MOSI and D/C clock nothing; a pad's own pull is the SoC's affair. | 2d-D4, RW §4. |
| 2d-R7 | **A wake pin's level during deep sleep** is the chip's drive, else the pull its IO MUX register gives the pad in sleep (`MCU_WPU/WPD` with `SLP_SEL`, else `FUN_WPU/WPD`) — after task 7 has read ESP-IDF 5.5.2's `gpio_deep_sleep_wakeup_prepare` and `esp_sleep_config_gpio_isolate` and confirmed or corrected this in RW §4. | 2d-D11, 2d-D12. |
| 2d-R8 | **Power-off is final for a life.** After `StopReason::PowerOff` the machine runs no instruction and accepts no input; a front end powers a new life on. The end is reported at the instant the supply failed. | 2d-D13. |
| 2d-R9 | **Session format 2 is the only one written**; format 1 is still read and holds no board input; a board input in a format-1 file is refused by name. | 2d-D10. |
| 2d-R10 | **Images are compared exactly.** A full refresh ends every pixel at 0 or 255 under SP2a's model (its `x4_driver` test): images A and C hold those two values only and the test compares every byte. Image B, a fast refresh, is compared the same way if task 2 shows that SP2a's reference fast waveform drives every changed pixel to its end (25 frames of 300 V·ms against a 6 000 V·ms swing, if all of one sign); otherwise image B is drawn with a full refresh and the fast one is checked by its kind (`Partial`) and its changed pixels only. | 2d-D21; no grey of the model is a measured value. |
| 2d-R11 | **The front end changes only where the spec says**: shades, the approximation note, the off state, the USB-power box of the start dialog, the pattern banner left for `origin: testPattern`. | 2d-D16 to 2d-D19. |
| 2d-R12 | **Raw controller RAM and the partial-refresh counter are not exposed** (SP4), nor a cable change during a life (SP4), nor the SD card (SP2e); each is named in the hand-over note with its heir. | Spec §7. |
