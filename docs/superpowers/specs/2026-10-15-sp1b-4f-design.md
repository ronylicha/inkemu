# SP1b-4f — PMP appliquée, mode utilisateur, groupe `pmp32` : design

Date : 2026-10-15. Spec globale : `docs/superpowers/specs/2026-10-11-inkemu-design.md` §10.2 point 5 (« CSR et
mécanisme d'interruption spécifiques au C3 »), §10.3 critère 1 (conformité). Découpage :
`docs/superpowers/notes/2026-10-14-sp1b-4-decoupage.md` (« Application de la PMP, groupe `pmp32` d'arch-test réactivé,
conformité complète »). Héritage : `docs/superpowers/notes/2026-10-11-sp1a-carryover.md` (PMP absente, `pmpaddr`
exclu, test CLI qui compte sur son échec), note de passation de SP1b-4e (« SP1b-4f : la PMP »), ADR 0008 et
`docs/lockstep-differences.md` (ligne 26). Recherche : `docs/research/esp32c3-pmp-and-user-mode.md` (PM ci-dessous),
`docs/research/sp1b-4-scoping.md` §1(d).

## 1. But

Faire respecter la PMP de l'ESP32-C3 telle que son TRM la décrit, modéliser le mode utilisateur que la puce a, et
réactiver en CI le groupe `pmp32` de riscv-arch-test contre Sail, sans changer ce que font les firmwares de référence.

## 2. Décisions

| # | Décision | Raison |
|---|---|---|
| L1 | **Le cœur de l'ESP32-C3 a un mode utilisateur** : `misa` `0x40101104` ; un `mret` avec `MPP` = 0 y entre, un piège en sort et range le mode d'où il vient dans `MPP` ; en mode U, un CSR dont les bits `[9:8]` dépassent le mode, `mret`, et `wfi` avec `TW` sont des instructions illégales ; `ecall` y a la cause 8 ; une interruption y est prise quel que soit `mstatus.MIE`. Pas de `MPRV` ni de `mcounteren` (absents du TRM). | TRM v1.4 registres 1.5, 1.6, 1.10 (PM §1) ; spécification privilégiée pour ce que le TRM ne dit pas (accès aux CSR, interruptions en mode U), comme QEMU et Sail. |
| L2 | **La PMP de la puce suit le TRM §1.8** : 16 entrées, granularité 4 octets, OFF/TOR/NA4/NAPOT ; **pas de priorité statique** : un accès réussit si une entrée qui s'applique le contient entièrement et l'autorise, échoue si une entrée qui s'applique en touche un octet sans qu'aucune l'autorise, sinon prend le défaut (machine : autorisé, utilisateur : refusé) ; en mode machine seules les entrées verrouillées s'appliquent. Lectures du TRM prises (PM §2) : une entrée qui ne contient qu'une partie de l'accès n'accorde rien ; un NAPOT au-delà de 1 Go est décodé comme la spécification le fait (HYPOTHÈSE, sonde sur une puce). | Le TRM documente la non-conformité ; sur la table d'ESP-IDF (16 TOR contiguës) la règle coïncide avec la priorité statique de QEMU (PM §3). |
| L3 | **Ce qu'une écriture garde, sur la puce, est ce que QEMU garde** : l'octet de `pmpcfg` entier (bits 5–6 compris), les 32 bits de `pmpaddr` ; une écriture R = 0 avec W = 1 laisse l'entrée telle quelle. Verrous : une entrée verrouillée gèle sa configuration et son adresse, une TOR verrouillée gèle aussi l'adresse au-dessous ; seul un reset les efface. | Le TRM renvoie à la spécification 1.10, qui laisse ces champs WARL ; QEMU est l'oracle du lockstep (PM §3). |
| L4 | **Le contrôle** : chaque parcelle de 16 bits d'un fetch, avant le cache de décodage ; chaque chargement et rangement après le contrôle d'alignement, avant le bus. Faute : cause 1, 5 ou 7, adresse fautive (de la parcelle ou de la donnée) dans `mtval`. Aucun cycle de plus (HYPOTHÈSE, comme QEMU). Le cache de décodage ne garde que des décodages : une écriture de la PMP prend effet au fetch suivant, sans invalidation. | TRM §1.8.3 et registre 1.11 ; Sail et QEMU contrôlent par parcelle (PM §3, §4, §6). |
| L5 | **Un cache de verdicts par page** (256 pages, direct, oublié à chaque écriture de la PMP) : une page dont chaque entrée applicable la contient entièrement ou pas du tout a un verdict uniforme ; sinon, et pour un accès qui franchit une fin de page, contrôle entrée par entrée. Un masque des entrées applicables par mode évite tout calcul quand aucune ne s'applique. | ESP-IDF verrouille 16 entrées : sans cache, chaque accès les parcourrait ; la règle est celle de QEMU pour ses pages de TLB. |
| L6 | **Le banc de conformité devient un cœur M+U avec PMP** (`Core::MachineUser`) : les choix de Sail configuré comme le banc — priorité statique, `MPP` non nominal légalisé en U, `MPRV`, `TW`, `mcounteren` (tous bits inscriptibles), bits 5–6 de `pmpcfg` lus à 0, `pmpaddr` sur 30 bits, R = 0/W = 1 ignoré. `inkemu rvtest` et les riscv-tests tournent dessus. Le cœur M seul reste le défaut de `HartConfig`. | La conformité compare au modèle de Sail, qui ne sait pas faire la règle de la puce ; le code partagé (décodage, verrous, modes, contrôles) est le même. |
| L7 | **`HartConfig::core: Core`** (`MachineOnly`, `MachineUser`, `Esp32C3`) remplace `vendor_csrs: VendorCsrs` ; `cpu_rv32::Privilege` et `Hart::privilege()` disent le mode. La PMP vit dans `cpu_rv32::pmp`, plus dans les CSR propres à l'ESP32-C3. | Le cœur est désormais plus que des CSR de vendeur ; une interface graphique (SP2) pourra afficher le mode. |
| L8 | **`pmp32` réactivé : 41 tests**, total 133. ISA `RV32IMCUZicsr_Zifencei`, `misa` `0x40101104` ; Sail : U, `PMP_Ignore`, `wfi_available_to_user_mode`. L'environnement d'arch-test est corrigé (`tools/conformance/riscof/arch-test-env-no-smode.patch`) : prologue et épilogue S et accès à `medeleg` retirés, gestionnaire et zone de sauvegarde S gardés ; empreinte de l'original vérifiée avant ; `patch` ajouté à l'image. Les fichiers de test ne sont pas touchés. `ARCH_TEST_ONLY` limite le script à quelques groupes (usage local). | 40 tests sur 41 supposent un mode S ; sans lui l'environnement boucle (mesuré, PM §5.2). Corrigé, les 41 terminent sur Sail M+U (PM §5.3). ADR 0010. |
| L9 | **riscv-tests** : `rv32mi-p-pmpaddr` sort de la liste d'exclusion (65 exécutés, 2 exclus) ; le test CLI d'échec de `rvtest` s'appuie sur un ELF synthétique, construit par le test, qui déclare l'échec du sous-test 1. | Report de SP1a. |
| L10 | **Lockstep** : aucune ligne ; ligne 26 et ligne 1 révisées (phrases), « Ce qui n'est pas comparé » complété. Le test synthétique `a_csrrsi_writes_only_its_immediate` pose R + W au lieu de W seul (combinaison réservée qu'inkemu ignore désormais, comme QEMU). | Une ligne appartient à une fenêtre qui l'utilise (R35) ; les différences de règles ne se montrent sur aucune fenêtre (PM §3). |
| L11 | **Rien ne change pour les firmwares de référence** : empreintes épinglées (12 s `a0d221296337b295`, 40 000 001 cycles `fb9ea628bc25b355`, `adc_wait_panic` `b217bc3b287080ae`, `deep_sleep_timer` `80bd1c43d55b5467`, CoreMark `bfb20978732b673f`), fenêtres du lockstep et leurs usages. | Aucune faute PMP dans ces exécutions ; QEMU applique déjà la PMP sur les fenêtres. |
| L12 | Documents : PM, ADR 0010, révisions du tableau des différences, `docs/registers-accepted-without-effect.md`, README (EN, FR), README de la conformité, note de passation, cartographie. | Traçabilité. |

## 3. Hors périmètre

- Le mode superviseur (la puce n'en a pas ; ADR 0010, alternatives).
- Les permissions `SENSITIVE` (PMS), le garde-pile d'`ASSIST_DEBUG`, les déclencheurs de débogage : sous-projet 4.
- Sonder une puce pour les lectures du TRM de L2 et L3 : sous-projet 8.

## 4. Critères d'acceptation

1. Les tests unitaires de `cpu-rv32` tiennent L1 à L5 (dont un test aléatoire qui compare le cache de verdicts aux
   règles, et un test qui échoue si le contrôle saute un décodage en cache : vérifié par mutation).
2. `tools/conformance/run-arch-test.sh` passe avec `pmp32` = 41 et 133 au total ; `riscv_tests` passe avec 65 tests.
3. Les empreintes de L11 sont inchangées ; les étapes du lockstep de la CI passent ; la CI est verte.
4. Les tests du lockstep (`cargo test -p lockstep`) passent, la ligne 26 inchangée dans ses paramètres et usages.
