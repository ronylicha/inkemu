# SP1b-4b — Enregistrement et rejeu des sessions : design

Date : 2026-10-14. Spec globale : `docs/superpowers/specs/2026-10-11-inkemu-design.md` (§6.4 : `inkemu replay
session.inkrec`, « une session enregistrée contient l'image, le profil et tous les événements » ; §10.2 point 9 ;
§10.3 critère 6 : « deux exécutions de la même session produisent la même empreinte de trace »). ADR 0004 (entrées
d'une exécution, fichier de flash) et ADR 0006 (entrées des consoles et de l'hôte USB). Cadrage :
`docs/research/sp1b-4-scoping.md` §1(c) ; découpage : `docs/superpowers/notes/2026-10-14-sp1b-4-decoupage.md`.

## 1. But

Une exécution peut être enregistrée dans un fichier `.inkrec` et rejouée : le rejeu redonne, à l'octet près, les
mêmes sorties de console, la même fin, le même temps d'appareil, le même nombre de cycles, la même empreinte de
trace et la même flash finale, quel que soit l'hôte et quel que soit le découpage. Un rejeu ne lit aucun chemin de
l'enregistrement, n'écrit rien, et dit précisément ce qui diffère s'il diverge.

## 2. Décisions

| # | Décision | Raison |
|---|---|---|
| G1 | **Journal des entrées acceptées dans la machine** (`soc-esp32c3`) : chaque entrée que la machine accepte (état de l'hôte USB à la mise sous tension, octets envoyés à une console avec leur date, changements d'hôte datés) est consignée dans l'ordre où la machine l'applique, dans les bornes d'ADR 0006 (1 Mio en attente par console, 16 384 changements d'hôte). Une entrée refusée n'est pas consignée. | ADR 0006 : la session porte les entrées « telles que la machine les a reçues », pas le script qui les a produites ; le même journal sert à la CLI, aux scripts et à la future interface. |
| G2 | **Nouvelle crate bibliothèque `session`** : format, écriture et lecture en mémoire (octets), pilote de rejeu sur une machine ; sans E/S hôte, compilée pour wasm32 comme `console-script`. La CLI ne fait que lire et écrire le fichier. | Tout doit se piloter depuis l'interface ; la version web (SP6) rejouera des sessions. |
| G3 | **Contenu d'une session** (format versionné `inkemu-session 1`) : identité de la ROM (révision, SHA-256 ; la ROM n'est jamais incluse, sa licence l'interdit) ; profil (identifiant et texte TOML complet, avec son SHA-256) ; flash de départ complète, compressée (deflate), avec son SHA-256 ; options qui changent l'exécution (`--strict-mmio`, limites `--max-cycles` et `--max-time`, limite effective atteinte) ; état de l'hôte USB à la mise sous tension ; entrées datées du journal G1 ; résultat attendu : raison de fin, temps d'appareil, cycles, instructions, empreinte de trace, SHA-256 de la flash finale, SHA-256 de chaque console. Aucun chemin, aucune heure de l'hôte. | ADR 0004 point 1 et ADR 0006 ; un contenu, pas un fichier. |
| G4 | **Lecture bornée** : le lecteur refuse un fichier d'une autre version, tronqué, dont une longueur dépasse sa borne constante (flash = taille maximale d'un profil, entrées = bornes d'ADR 0006, texte du profil 64 Kio), ou dont une empreinte ne correspond pas ; chaque refus nomme le champ et la cause. | Un fichier est une entrée non fiable ; aucune allocation pilotée par une longueur non bornée. |
| G5 | **`inkemu run --record <fichier>`** : écrit la session à la fin de l'exécution, quelle qu'en soit la fin (limite, arrêt strict, sommeil sans fin, Ctrl-C). Une exécution arrêtée par Ctrl-C est enregistrée avec son point d'arrêt (cycles et temps d'appareil) comme limite explicite, ce qui la rend rejouable. Avec `--flash-file`, la flash de départ est le contenu lu au démarrage, enregistré tel quel ; le fichier de flash n'est pas lu par le rejeu. | ADR 0004 : la fin d'une exécution interrompue dépend de l'hôte ; l'enregistrer comme limite supprime cette dépendance. |
| G6 | **`inkemu replay <fichier>`** : vérifie la ROM disponible (même SHA-256, sinon refus qui dit `inkemu rom fetch`), reconstruit la machine depuis la session, réapplique les entrées à leurs dates, s'arrête à la même limite, affiche la console comme `run`, puis compare le résultat à celui enregistré. Code de sortie 0 si tout est identique ; un code nouveau, **6**, si le rejeu diverge, avec la première grandeur qui diffère et ses deux valeurs. Le rejeu n'écrit aucune flash. | Spec §6.4 ; « le code de sortie fait foi ». |
| G7 | **Critère 6 tenu par des tests** : une même session rejouée deux fois donne la même empreinte ; une session rejouée en tranches de 1, 7, 997 et 7 919 cycles donne le même résultat ; des sessions qui traversent un reset, un sommeil profond, des entrées de console et des changements d'hôte. | La propriété du projet, prouvée sur des sessions. |
| G8 | **ADR 0007** « format des sessions » (français, comme les ADR 0004 à 0006) : contenu, version, bornes, ce qui n'y est jamais (ROM, chemins, heure de l'hôte), comportement du rejeu. | Décision durable qui engage la version web et l'interface. |
| G9 | **Preuve en CI** : tests unitaires et d'intégration dans le job `check` (firmwares écrits en instructions) ; un test `#[ignore]` de `run_cli` dans `reference-boot` (effectif +1) qui enregistre une exécution d'une application de référence pilotée par un script de console, puis la rejoue et compare. | Ce qui compte : une vraie application ESP-IDF, des entrées datées, un reset. |
| G10 | Documents : README (commandes `--record` et `replay`, code de sortie 6), note de passation `2026-10-14-sp1b-4b-carryover.md`. | Traçabilité. |

## 3. Hors périmètre

- Le lockstep (SP1b-4c/4d) : il comparera deux machines parties du même contenu, et pourra partir d'une session.
- Les instantanés d'état (reprendre une exécution au milieu) : non demandés par la spec.
- Les entrées de SP2 (boutons, carte SD) : elles rejoindront le journal G1 quand elles existeront ; le format est
  versionné pour cela.

## 4. Erreurs

- Fichier de session illisible, d'une autre version, tronqué, hors bornes, empreinte fausse : refus avant toute
  exécution, avec le champ et la cause (spec §7).
- ROM absente ou différente : refus qui nomme le SHA-256 attendu et la commande `inkemu rom fetch`.
- Écriture du fichier impossible à la fin : code 2 (3 après un arrêt strict), comme le fichier de flash.

## 5. Critères d'acceptation

1. `inkemu run --record s.inkrec …` puis `inkemu replay s.inkrec` sort 0 et affiche la même console, pour une
   exécution avec script de console, reset et sommeil profond.
2. Une session modifiée (un octet d'entrée changé) rejoue en divergeant : code 6 et grandeur nommée.
3. La CI est verte sur ses cinq jobs, effectif de `reference-boot` +1.
